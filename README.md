# 星星村 · 黑白像素迷宫

复刻 90 年代 Game Boy《精灵宝可梦》的画面与交互语言，做的一个纯黑白像素迷宫小游戏。
为 5 岁小朋友设计：大格子、没有倒计时、走错可以回头、迷路有人指路。

打开 `index.html` 就能玩，单文件、零依赖、离线可跑。

## 玩法

收集地图上的 **5 颗星星**，然后走进小屋就通关。

| 操作 | 说明 |
|---|---|
| 方向键 / WASD | 走路（只能上下左右四向） |
| 点地图格子 | 自动寻路走过去 |
| Z / 空格 / 回车 | 问村长要提示；对话中按此翻页 |
| R | 换一个迷宫 |

没有倒计时，没有失败，走错就回头。

## Game Boy味道在哪

不是滤镜，是几条硬规矩：

- **严格 1-bit**：全画面只有纯黑和纯白两种颜色（实测灰阶像素 0种）。
  绘制时先画到离屏 canvas，再按亮度阈值化（lum < 140 → 黑）强制二值化。
- **格子对齐**：13×13 格迷宫，每格 12px。走路是**一格一格跳**（150ms/格），没有平滑移动。
- **两帧走路动画**，转向时脚会跳一下——这种"卡"不是缺陷，是重量感。
- **对话框三条规矩**（照搬 GB 做法）：
  1. 说话人名字贴在框的**左上角外面**
  2. 固定占底部高度，把地图压掉一截
  3. 右下角 ▼ 闪烁 = 下面还有一段，按键翻页
- **撞墙没有音效**，只有静默的拒绝。老游戏的材质感就是这么来的。
- **单声道方波音效**，模拟 GB 的 4 声道里那一个"人声"。

## 面向小朋友的设计

- 格子做到 12px，手机上能整数放大到 2 倍，手指点得准
- 迷宫密度经过参数标定：空地率 80%、平均死胡同 2.8 个、起点到门约 8 步
  （更狠的参数会到 6.4 个死胡同，对小孩太难）
- 按 Z 问村长，他给的**方向是真算出来的**：挑当前最近的星星，用 BFS 算出第一步，不是随机糊一句
- 小屋没锁时会显示还差几颗星星，不让孩子白跑

## 迷宫生成

用的是**房间式生成器**，不是常见的递归回溯。

原因：递归回溯生成的"细杆迷宫"通道恒为 1 格宽，**2×2 连续空地永远不存在**
（相邻空格之间必有墙），而小屋要占 2×2 ——会直接导致开局放不下小屋。
房间式生成天然有 2×2 空地，通道也更宽敞，适合小孩。

连通性有三层兜底：洪水填充找孤立格 → 凿最短隧道 → 顶部重试循环直到门必定可达。
小屋若被放到角落导致门被自己封死，`openDoorExit()` 会现场凿开出路。

## 本地验证

```bash
node tools/verify-maze.js
```

无头跑 5000 局，检查可解性、连通性、提示方向正确性。当前结果：

```
找不到小屋          0
门不可达            0
星星放不满 5 颗      0
提示方向错误         0
平均空地占比        80%
平均死胡同          2.8 个
```

## 浏览器支持

需要支持 ES6 与 canvas 的现代浏览器。因为用到了 `getImageData`，
直接双击本地打开（`file://`）就能跑，不需要起服务器。
